# Summary

Host identities control access to Linux files, processes and privileged interfaces independently of Kubernetes identities. A non-root account can still hold powerful authority through groups, writable service definitions or elevation rules.

Least privilege requires a defined task, a narrow working grant and accountable use. Credential removal, session handling and durable configuration must align when access changes, with a controlled recovery path for legitimate operations.
