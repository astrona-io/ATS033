# Lock And Expire A Departed Account

The learner disables the node account `departed-user` without deleting it: lock the password, set an account expiry date in the past and change the shell to `/usr/sbin/nologin`. The learner then closes `root` and password logins in the real SSH daemon (sshd) with a drop-in file, `sshd -t` and `systemctl reload ssh`. The account `pilot` must stay unchanged.

The lab runs in a QEMU virtual machine built from the pinned CKS image `ghcr.io/astrona-io/ubuntu-qcow2-image:24.04-cks-20261118-{ARCH}`. `vm/install.sh` (generated by `scripts/ci/vm-lab.py`) builds a one-node kubeadm cluster, copies the lab to `/opt/astrona-lab` and runs `bootstrap/setup.sh`. Setup creates both accounts with real password hashes through `chpasswd`, so `passwd -S` starts as `P` and the lock check fails at start. It also installs `/etc/ssh/sshd_config.d/10-migration-access.conf` with `PermitRootLogin yes` and `PasswordAuthentication yes` and reloads ssh. The expiry check confirms that `su` to the account fails, which is the PAM account check and not only a field in `/etc/shadow`. The sshd check reads `sshd -T` and also probes the running daemon with a `BatchMode=yes` login to `127.0.0.1`, so a file change without a reload fails.

Live run on 2026-11-18 (arm64, hvf): `astrona test -c lab-02` ran `testing/verify-start.sh`, which proved that all four outcomes fail on the starting state. After `solution/apply.sh`, all four outcomes passed (`4 passed, 0 failed`, `PROCTOR: PASS`) in about 75 seconds, VM start included.
