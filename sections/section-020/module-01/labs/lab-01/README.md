# Grant Read Access Through A Group

The learner gives one node account read access to one file through a group: `chgrp` and `chmod 0640` on `/srv/flight-logs/telemetry.log`, then `usermod --append --groups flight-log-readers navigator`.

The lab runs in a QEMU virtual machine built from the pinned CKS image `ghcr.io/astrona-io/ubuntu-qcow2-image:24.04-cks`. `vm/install.sh` (generated by `scripts/ci/vm-lab.py`) builds a one-node kubeadm cluster, copies the lab to `/opt/astrona-lab` and runs `bootstrap/setup.sh`, which creates the accounts, the group and the file on the VM only. The two outcomes are behaviour checks: a real read with `runuser -u navigator -- cat`, and a denied read with `runuser -u cadet -- cat`.

Live run on 2026-11-18 (arm64, hvf): `astrona test -c lab-01` ran `testing/verify-start.sh`, which proved that both outcomes fail on the starting state. After `solution/apply.sh`, both outcomes passed (`2 passed, 0 failed`, `PROCTOR: PASS`) in about 35 seconds, VM start included. Every command output in `solution.md` comes from a manual walkthrough in an `astrona run` VM of the same image that day.
