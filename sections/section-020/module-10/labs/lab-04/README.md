# Record Every Change To The Sudo Rules

The learner adds a persistent `auditd` watch rule on `/etc/sudoers.d` in `/etc/audit/rules.d/40-sudoers.rules`, loads it with `augenrules --load`, adds the sudoers file `/etc/sudoers.d/40-oncall` for the account `oncall`, and confirms that the audit log recorded the change. The existing persistent watch on `/etc/sudoers` must stay loaded.

The lab runs in a QEMU virtual machine built from the pinned CKS image `ghcr.io/astrona-io/ubuntu-qcow2-image:24.04-cks`. `vm/install.sh` (generated by `scripts/ci/vm-lab.py`) builds a one-node kubeadm cluster, copies the lab to `/opt/astrona-lab` and runs `bootstrap/setup.sh`. Setup creates `oncall`, writes `/etc/audit/rules.d/30-sudoers-main.rules` and loads it. The persistence outcome uses `augenrules --check`, which prints `No change` only when `/etc/audit/audit.rules` was rebuilt from `rules.d`. The record outcome uses `ausearch --input-logs -k sudoers-change -f /etc/sudoers.d/40-oncall`, which exits 1 with `<no matches>` when the file was written before the watch was loaded (seen live). Every outcome also checks the guarded rule file and its loaded rule.
