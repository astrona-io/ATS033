# Close The Kubelet API To Anonymous Callers

The lab runs a one-node kubeadm cluster in a QEMU VM (`runtime.type: qemu`). `vm/install.sh` builds the cluster and runs `bootstrap/setup.sh`, which creates the namespace `starfleet-033-030-03-03` and the ServiceAccount `metrics-reader` (no RBAC permissions). It then sets `authentication.anonymous.enabled: true` and `authorization.mode: AlwaysAllow` in `/var/lib/kubelet/config.yaml` on the node, restarts the kubelet and waits until an anonymous `curl` to `https://127.0.0.1:10250/pods` returns `200`. The learner works as `student` through `astrona ssh astro-ats-033-lab-030-03-03`, restores the secure settings with `sudo` and restarts the kubelet.

Outcomes (1 point each):

- `anonymous-auth-disabled`: the running configuration (`/api/v1/nodes/<node>/proxy/configz`) has `authentication.anonymous.enabled: false`, and an anonymous `curl` on the node to the kubelet gets `401`.
- `webhook-authorization`: the running configuration has `authorization.mode: Webhook`, and a `metrics-reader` token gets `403` from the kubelet.

Guards: the node is Ready and the running kubelet keeps `authentication.webhook.enabled: true`.

The files under `vm/` are generated by `scripts/ci/vm-lab.py`; regenerate them after any change to a lab file. Run `astrona test` on this folder: `vm/verify-start.sh` checks that every outcome fails on the starting state, then the reference solution is applied and every outcome must pass. Live run on 2026-11-18 (QEMU image `24.04-cks` build 20261118, Kubernetes `v1.35.10`): `astrona test` ended with `PROCTOR: PASS` (2/2). In a separate `astrona run`, both the anonymous request and the `metrics-reader` token got `200` on the start state; after the change and a kubelet restart they got `401` and `403` (`Forbidden (user=system:serviceaccount:starfleet-033-030-03-03:metrics-reader, verb=get, resource=nodes, subresource(s)=[pods proxy])`) and the node stayed Ready.
