# Restrict The etcd Data Directory

The lab runs a one-node kubeadm cluster in a QEMU VM (`runtime.type: qemu`). `vm/install.sh` builds the cluster and runs `bootstrap/setup.sh`, which runs `chmod 755 /var/lib/etcd` on the node. The learner works as `student` through `astrona ssh astro-ats-033-lab-030-03-04`, reads `--data-dir` from `/etc/kubernetes/manifests/etcd.yaml` and sets the directory back to mode `700` with `sudo`.

Outcome (2 points):

- `etcd-data-directory-mode`: `stat -c '%a %U %G' /var/lib/etcd` on the node returns `700 root root`.

Guards: etcd answers `https://127.0.0.1:2379/health` with `"health":"true"` when called with the `apiserver-etcd-client` certificate, and `kubectl get --raw /readyz` returns `ok`.

The files under `vm/` are generated by `scripts/ci/vm-lab.py`; regenerate them after any change to a lab file. Run `astrona test` on this folder: `vm/verify-start.sh` checks that every outcome fails on the starting state, then the reference solution is applied and every outcome must pass. Live run on 2026-11-18 (QEMU image `24.04-cks` build 20261118, Kubernetes `v1.35.10`): `astrona test` ended with `PROCTOR: PASS` (2/2). In a separate `astrona run`, `stat` showed `755 root root /var/lib/etcd` on the start state; after `sudo chmod 700` it showed `700 root root /var/lib/etcd`, etcd reported `{"health":"true","reason":""}` and `/readyz` returned `ok`.
